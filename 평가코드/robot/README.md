# 로봇 스크립트 (PICKNPLACE_FULL)

`PICKNPLACE_FULL_main.js`는 **초안**이다. 현장 확인 전이다. 아래 확인 목록을 실물에서 확인하고 결과를 적는다.
쪽수 표기: R = Rodi Script Programming Guide_KR, H = HCR_2G_UserGuide_KR_V2.2.

## 1. 붙여 넣는 방법

1. GUI 프로그램의 Main에 스크립트 명령 하나를 둔다.
2. `PICKNPLACE_FULL_main.js` 전체를 붙여 넣는다.
3. `HOME`, `PICK`을 티칭 값으로 바꾼다. 유효성 검사를 누른다.

## 2. 컨트롤러 I/O 설정

DI0~DI3, DO0·DO1에 명령 기능(Program Pause 등)을 **지정하지 않는다**(Unassigned). 감시 스레드와 섞이지 않게 하기 위해서다.

## 3. 자동 시작

기본 프로그램으로 지정하고, 부팅 시 자동 시작 조건을 둔다 (H p236).

## 4. 완료 기준 시험 (tasks 4절)

PLC 없이 펜던트에서 DI를 흉내 내어 DO0·DO1을 확인한다.

1. 스크립트1: 펜던트에서 DI0을 켜면 DO0이 켜진다. 그때 DI0을 끈다(PLC 역할). 끄지 않으면 이동이 끝나도 DO0이 켜져 있다(요청이 꺼질 때까지 유지하는 규칙). DI0을 끄면 이동이 끝날 때 DO0이 꺼진다.
2. 스크립트2: 펜던트에서 DI1을 켜면 DO0이 켜진다. 그때 DI1을 끈다(PLC 역할). 끄지 않으면 이동이 끝나도 DO0이 켜져 있다(요청이 꺼질 때까지 유지하는 규칙). DI1을 끄면 이동이 끝날 때 DO0이 꺼진다.
3. 이동 도중에 DI3를 켜고 꺼서 정지와 재개도 본다. 켜면 멈추고 DO1이 켜진다. 끄면 DO1이 꺼지고 이어서 간다.

## 5. 안전

- 첫 실행은 저속으로 한다.
- 하드웨어 E-stop을 손 닿는 곳에 둔다.
- UI의 즉시 정지는 비상정지가 아니다.

## 6. 요청과 DO0 (2026-11-10 강사 결정)

1. PLC가 요청(DI0 또는 DI1)을 켠다. 메인이 보고 스크립트1(또는 2)을 부른다.
2. 스크립트가 DO0을 켜고 이동한다.
3. PLC는 DO0을 보면 요청을 끈다.
4. 스크립트는 이동이 끝나고 DI0·DI1이 모두 꺼진 뒤에 DO0을 끈다(`waitAllOff`).

이미 목표 위치에서 부르면 이동은 거의 0초다. 그래도 DO0은 요청이 꺼질 때까지 켜져 있으므로 PLC가 놓치지 않는다.
요청이 꺼지지 않는 고장이면 DO0을 켠 채 기다린다. 다시 실행하지는 않는다.

## 대안

3~5번이 실패할 때만 쓴다.

### 대안 1. 컨트롤러 I/O 설정 방식

- 설정: DI3 → Program Pause(High), DO1 → Program Paused (H p107~108)
- 재개: DI3 OFF로 재개되지 않으면 DI2 → Program Play로 지정한다. 래더가 9993에서 P46을 0.5초 켠다.
- 스크립트에서 감시 스레드를 뺀다.
- **위험:** H p63에 "프로그램이 실행 중이 아니면 출력 LOW"가 있다. 일시정지 중에 DO0이 꺼지고, 재개 직후 DO0·DO1이 동시에 OFF인 순간이 있으면, PLC가 그 순간을 "스크립트 끝"으로 볼 수 있다. 그러면 자동 운전 중에 이동 도중 그리퍼가 동작한다. 이 방식을 쓰면 통합 시험 4에서 PLC 모니터로 반드시 확인한다.

### 대안 2. popup 일시정지

감시 스레드에서 `popup(메시지, 1, id)`(1 = Suspend, R 8382~8420)로 프로그램을 일시정지하고 `popupClose(id)`로 푼다. 단, Suspend가 스레드까지 멈추는지는 문서에 없다. 멈춘다면 재개할 수 없다. opts 형식이 문서끼리 다르다.

`halt()`(R 8260)는 프로그램 종료라서 재개가 안 되므로 즉시 정지에 쓰지 않는다.
