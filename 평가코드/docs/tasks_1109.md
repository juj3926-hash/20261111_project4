# 11/9 과제 — PC → PLC → 로봇 픽앤플레이스 구현

근거: `1109_구현.pptx` 슬라이드 11~30 (신호 흐름도, 고장 코드, 신호 맵)

## 0. 목표

PC 화면의 버튼으로 로봇과 그리퍼를 제어해 픽앤플레이스를 수행한다.

```
로봇 이동1 → 그리퍼 닫기(3초) → 로봇 이동2(원위치) → 그리퍼 열기(3초)
```

- **순서는 PC가 정한다.** PC가 이동 명령을 하나씩 보낸다.
- **PLC가 하는 일:**
  - 명령을 받아 로봇과 그리퍼로 전달한다.
  - 상태를 하나의 코드로 만들어 PC에 보여 준다.
  - 자동 운전 중에는 이동이 끝나면 그리퍼를 알아서 제어한다.
- 개별 버튼(스크립트1·2, 그리퍼 열기/닫기)도 있다. **로봇이 정지 상태일 때만** 쓸 수 있다.

**완성 기준:** 아래 6절의 시험 표를 모두 통과하고, PC 로그로 증명한다.

## 1. 고정된 신호 (강사 제공 — 바꾸지 않는다)

### 1.1 PLC ↔ 로봇 배선

| PLC | 로봇 | 신호 | 뜻 |
| --- | --- | --- | --- |
| OUT P44 | DI0 | 이동1 요청 | 켜지면 로봇이 스크립트1 시작 |
| OUT P45 | DI1 | 이동2 요청 | 켜지면 로봇이 스크립트2 시작 |
| OUT P46 | DI2 | (예약) 상태 요청 | 이번에는 쓰지 않는다. 로봇 상태는 DO0을 계속 읽는다 |
| OUT P47 | DI3 | **즉시 정지** | 켜져 있는 동안 로봇이 그 자리에서 멈춘다. 꺼지면 재개 |
| IN P04 | DO0 | 로봇 동작 중 | 스크립트 실행 중이면 ON, 끝나면 OFF |
| IN P05 | DO1 | 로봇 비정상 정지 | 즉시 정지나 오류로 멈춰 있으면 ON |
| OUT COM3 | DI쪽 24V (아무 한 점) | 공통 | |
| IN COM | DO쪽 0V | 공통 | |

- P46과 P47이 P44·P45와 **같은 COM3 그룹인지 PLC 단자대에서 확인한다.** COM3에는 로봇 24V가 들어간다.
- 그리퍼 밸브는 아직 도착하지 않았다. 출력 주소는 도착하면 정하고, 그 전에는 5절의 대체 방법을 쓴다. 그리퍼 출력은 COM3 그룹을 피한다.
- **11/6 E2E와 다른 점:** DO0과 DO1의 뜻이 바뀌었다. 예전에는 "이동1 종료", "이동2 종료"였고, 이제는 "동작 중", "비정상 정지"다. 로봇 스크립트도 새로 맞춘다.

### 1.2 PC → PLC 명령 (D01001 = Modbus 쓰기 주소 **1**)

| 코드 | 명령 | PLC가 받는 조건 | PLC 동작 |
| --- | --- | --- | --- |
| 1111 | 자동 운전 시작 | 로봇 정지, 그리퍼 열림, 자동 운전 아님 | 자동 운전 표시를 켠다 |
| 9991 | 로봇 이동1 | 로봇 정지, 그리퍼 동작 중 아님 | DI0 요청 |
| 9992 | 로봇 이동2 | 로봇 정지, 그리퍼 동작 중 아님 | DI1 요청 |
| 9995 | 즉시 정지 | 언제나 | DI3 ON |
| 9993 | 재개 | 즉시 정지 중일 때 | DI3 OFF |
| 9994 | 자동 운전 해제 | 로봇 정지, 그리퍼 동작 중 아님 | 자동 운전 표시를 끈다. 이후 이동 뒤 자동 그리퍼 없음 |
| 3333 | 그리퍼 제어 (전환) | 로봇 정지, 그리퍼 동작 중 아님 | 지금 열림이면 닫기, 닫힘이면 열기. 출력 3초 뒤 그리퍼 상태가 바뀜 |
| 2222 | 상태 확인 | 언제나 | 접수만 한다. 명령 경로가 살아 있는지 확인하는 용도 |

3333은 상태를 바꾸는 명령이다. 그래서 PC는 보내기 전에 D01000의 그리퍼 자리로 지금 상태를 확인하고, UI 버튼에도 그 상태를 표시한다.

**명령 처리 규칙 (우편함 방식)**
1. PC는 D01001에 코드를 한 번 쓴다.
2. PLC는 코드를 처리하면 **D01001을 0으로 지운다.** 받든 거부하든 똑같이 지운다.
3. PC는 D01001이 0이 된 것으로 PLC가 처리했음을 안다(주소 1을 읽는다).
4. 받았는지 거부했는지는 D01000의 PLC 자리로 안다(1.3절).
5. 같은 명령을 다시 보낼 때는 0이 된 것을 확인한 뒤에 쓴다.

### 1.3 PLC → PC 상태 (D01000 = Modbus 읽기 주소 **0**)

```
상태 코드 = 1 + 로봇 + 3 × 그리퍼 + 6 × PLC        (0001 ~ 0012)
```

| 자리 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| 로봇 | 동작 중 (PLC가 DI0·DI1 요청 중이거나 DO0 ON) | 정지 (요청 없음, DO0·DO1 모두 OFF) | 비정상 정지 (DO1 ON) |
| 그리퍼 | 열림 | 닫힘 | |
| PLC | 정상 (마지막 명령을 받음) | 이상 (마지막 명령을 거부함, 또는 모르는 코드) | |

| 코드 | PLC | 그리퍼 | 로봇 | 코드 | PLC | 그리퍼 | 로봇 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 0001 | 정상 | 열림 | 동작 중 | 0007 | 이상 | 열림 | 동작 중 |
| 0002 | 정상 | 열림 | 정지 | 0008 | 이상 | 열림 | 정지 |
| 0003 | 정상 | 열림 | 비정상 정지 | 0009 | 이상 | 열림 | 비정상 정지 |
| 0004 | 정상 | 닫힘 | 동작 중 | 0010 | 이상 | 닫힘 | 동작 중 |
| 0005 | 정상 | 닫힘 | 정지 | 0011 | 이상 | 닫힘 | 정지 |
| 0006 | 정상 | 닫힘 | 비정상 정지 | 0012 | 이상 | 닫힘 | 비정상 정지 |

- PC에서 코드를 자리별로 나누는 식(n = 코드 − 1):
  - 로봇 = n % 3
  - 그리퍼 = (n // 3) % 2
  - PLC = n // 6
- **로봇 자리는 PLC가 이동 명령을 접수하는 순간부터 "동작 중"이다.** 로봇이 DO0을 켜기 전에도 마찬가지다. 그래서 접수 직후에 읽어도 "벌써 끝났다"로 잘못 보지 않는다.
- **그리퍼 자리는 3초 대기가 끝난 뒤에 바뀐다.** 센서가 없어서 3초가 지나면 완료로 본다. 그래서 PC는 그리퍼 자리가 바뀌는 것을 "그리퍼 제어 완료"로 쓴다.
- PLC 자리는 다음 명령을 받으면 0으로 돌아간다.
- PLC는 상태 코드를 매 스캔 다시 계산해 D01000에 쓴다.
- **PC는 원시 코드끼리 비교하지 말고 자리별로 나눠서 판단한다.** 거부가 한 번 일어나 PLC 자리가 1이 되면 모든 코드에 6이 더해진다(0005 → 0011).

### 1.4 자동 운전 순서 (PC가 순서 관리, 슬라이드 12~15)

| # | PC가 하는 일 | PLC·로봇 | PC가 기다리는 상태 |
| --- | --- | --- | --- |
| 1 | `1111` | 자동 운전 시작 | 0002 (정지, 열림) |
| 2 | `9991` | DI0 → 스크립트1 | 로봇 자리가 0(동작 중)이 됐다가 다시 1(정지) |
| 3 | 기다림 | **PLC가 알아서 그리퍼를 닫음 (3초)** | 0005 (정지, 닫힘) |
| 4 | `9992` | DI1 → 스크립트2 (원위치) | 로봇 자리 0 → 1 |
| 5 | 기다림 | **PLC가 알아서 그리퍼를 엶 (3초).** 자동 운전 끝 | 0002 (정지, 열림) = 한 사이클 완료 |

- 자동으로 그리퍼를 제어하는 것은 **자동 운전 중일 때만**이다. 개별 버튼으로 스크립트를 돌렸을 때는 로봇만 움직인다.
- **정지 버튼 (스크립트 끝까지 실행 후 정지):**
  1. PC가 다음 이동 명령을 보내지 않는다. 지금 진행 중인 단계(자동 그리퍼 포함)는 끝까지 간다.
  2. 단계가 끝나 로봇 정지와 그리퍼 대기 끝이 확인되면 `9994`(자동 운전 해제)를 보낸다.
  3. 이후에는 개별 버튼을 쓸 수 있고, 시작(`1111`)으로 새 사이클을 시작할 수 있다. 1111은 그리퍼가 열려 있어야 받으므로, 필요하면 먼저 3333으로 연다.
- **즉시 정지 버튼:** `9995`를 보낸다. 로봇이 그 자리에서 멈추고 상태가 비정상 정지가 된다. `9993`(재개)을 보내면 이어서 진행하고, 자동 운전이면 그리퍼 단계도 이어서 한다.
- 자동 운전 중에는 UI의 개별 버튼(스크립트1·2, 그리퍼)을 비활성화한다.

### 1.5 PLC → 로봇 요청 규칙

PLC는 DI0(또는 DI1)을 켠다. 로봇의 DO0(동작 중)이 켜지는 것을 보면 요청을 끈다. 로봇은 **요청이 켜지는 순간** 스크립트를 시작한다.

### 1.6 PLC 시작(RUN) 시 초기화

그리퍼는 기본 상태가 닫힘이라, PLC가 처음에 가정한 상태와 실제가 다를 수 있다. 그래서 첫 스캔에 다음을 한다.
1. **열기 출력을 3초 켜서** 실제 그리퍼를 열고, 상태 비트를 "열림"으로 맞춘다. 3초 동안은 "그리퍼 동작 중"이라 명령을 받지 않는다.
2. D01001을 0으로 한다. 자동 운전 표시, 요청 출력(DI0·DI1·DI3), PLC 이상 비트는 모두 끈다.

## 2. 할 일 1 — 통신 주소 확인 (래더 쓰기 전에)

1. **D01001 쓰기 확인:** QModMaster나 목요일 프로그램으로 **주소 1에 2222**를 쓴다. XG5000 모니터에서 **D01001 = 2222**인지 본다.
2. **D01000 읽기 확인:** XG5000에서 D01000에 아무 값이나 넣고, PC가 **주소 0**으로 같은 값을 읽는지 본다.
3. **한 번에 두 워드 읽기 확인:** FC03 **주소 0, 수량 2**로 읽으면 [D01000, D01001]이 한 번에 온다. PC 프로그램은 이 한 번의 읽기로 상태와 우편함을 함께 본다.
4. 값은 모두 10진으로 대조한다. XG5000 모니터가 16진 표시면 `2222`가 `08AE`로 보인다.

완료 기준: 두 주소가 맞는다는 것을 캡처나 로그로 남긴다. 주소 1 쓰기가 실패하면 강사에게 알린다. Cnet 매핑을 다시 봐야 한다.

## 3. 할 일 2 — PLC 래더 (XG5000)

다음을 래더로 만든다.

- **명령 해석:** `= D01001 코드` 비교 접점으로 명령마다 비트를 만든다.
- **받는 조건 판단:** 1.2절의 조건이 맞으면 받고, 아니면 거부한다. 모르는 코드도 거부다.
- **우편함 처리:** 받든 거부하든 D01001을 0으로 지운다. 거부했으면 PLC 이상 비트를 켜고, 받았으면 끈다.
- **로봇 요청:** DI0·DI1을 켜고 DO0이 켜지면 끈다(1.5절). DI3는 9995로 켜고 9993으로 끈다. 상태 코드의 "동작 중"에는 요청 중인 시간도 포함한다(1.3절).
- **그리퍼:** 3333을 받으면 지금 상태의 반대쪽 출력을 3초 켠다(열림이면 닫기, 닫힘이면 열기). 3초 동안은 "그리퍼 동작 중"이고, 끝나면 그리퍼 상태 비트를 바꾼다. 닫기와 열기 출력은 서로 인터록한다.
- **자동 운전:**
  - 1111을 받으면 자동 운전 표시를 켠다.
  - 자동 운전 중에 스크립트1이 끝나면(DO0 하강) 자동으로 닫기, 스크립트2가 끝나면 자동으로 열기를 한다.
  - 열기가 끝나면 자동 운전을 끈다. 9994를 받아도 끈다.
- **상태 코드:** 매 스캔 `1 + 로봇 + 3×그리퍼 + 6×PLC`를 계산해 D01000에 쓴다.
- **첫 스캔:** 1.6절 초기화(열기 3초 포함)를 한다.

완료 기준: 로봇 없이 XG5000에서 확인한다. 강제 입력으로 P04·P05를 켜고 끄면서 1.4절 순서대로 상태 코드가 바뀌는 것을 본다.

## 4. 할 일 3 — 로봇 스크립트 (티치 펜던트)

- **스크립트1:** DI0이 켜지는 순간 시작한다.
  1. DO0 ON
  2. 이동 (물건 집는 위치까지)
  3. 요청(DI0)이 꺼질 때까지 기다린다
  4. DO0 OFF
- **스크립트2:** DI1이 켜지는 순간 시작한다.
  1. DO0 ON
  2. 이동 (원위치)
  3. 요청(DI1)이 꺼질 때까지 기다린다
  4. DO0 OFF
- 요청이 꺼질 때까지 DO0을 켜 두는 이유: 이미 그 위치에 있으면 이동이 거의 0초라도 PLC가 DO0을 보고 요청을 끌 수 있어야 한다 (2026-11-10 강사 결정).
- 형식은 슬라이드 23과 같다. 다만 `DOUT(9)` 자리에 **DO0**을 쓴다.
- **실행 구조:** 로봇에는 **DI0과 DI1을 기다리는 메인 프로그램이 계속 돌고 있어야** 한다. 이 메인 프로그램이 신호를 받아 스크립트1·2를 부른다. 시험할 때는 로봇을 자동(원격) 실행 상태로 둔다.
- **즉시 정지:**
  - DI3가 ON이면 그 자리에서 멈추고 DO1을 ON한다.
  - DI3가 OFF가 되면 DO1을 OFF하고 이어서 동작한다.
  - 한화 컨트롤러에서 입력으로 일시정지·재개하는 방법을 매뉴얼이나 티치 펜던트에서 찾는다.
  - **먼저 확인할 것:** 스크립트가 이동 명령 사이사이에 DI3를 확인하는 방식이면, 지금 하는 이동(MOVEL 등)을 다 마친 뒤에야 멈춘다. "그 자리에서 즉시" 멈추려면 컨트롤러의 입력 기능(예: Flexible input에 일시정지·재개 할당)이 필요하다. 그 경우 일시정지 중에는 스크립트가 돌지 않으므로, DO1도 컨트롤러의 상태 출력 기능으로 켜야 할 수 있다. 확인 결과를 시험 기록에 적는다.

완료 기준: PLC 없이 티치 펜던트에서 DI를 흉내 내어 시험한다. DO0·DO1이 위 규칙대로 바뀌는지 확인한다.

## 5. 할 일 4 — 배선, 그리고 장비가 없을 때 대체 방법

- **배선:** 1.1절 표대로 한다.
  - 연결하기 전에 COM3 그룹을 확인한다.
  - 로봇 단자대의 0V·24V가 공통인지 테스터로 확인한다.
  - 이전 실습 배선이 남아 있으면 정리한다.
- **그리퍼(미도착):** 닫기·열기 출력은 M 비트로 대신하고, XG5000 모니터로 3초 동작을 확인한다. 밸브가 오면 그 비트 자리만 P 출력으로 바꾼다.
- **로봇 없이 시험:** XG5000 강제 입력으로 P04(동작 중)와 P05(비정상 정지)를 켜고 끈다.

## 6. 할 일 5 — PC 프로그램 + UI

목요일의 비동기 통신 코드(`plc_project.py`)나 월요일 수업 코드(`app.py`, `ui.js`)를 확장한다. UI 형태는 자유지만 **버튼과 로그 창이 있어야** 한다.

- **버튼:**
  - 시작 (자동 운전 한 사이클)
  - 정지 (스크립트 끝까지 실행 후 정지. 단계가 끝나면 9994를 보냄)
  - 즉시 정지
  - 재개
  - 스크립트1, 스크립트2
  - 그리퍼 (3333: 열림↔닫힘 전환. 버튼에 지금 상태를 표시)
- **상태 표시:** 주소 0부터 2개(D01000 상태, D01001 우편함)를 주기적으로 읽어 로봇, 그리퍼, PLC 상태를 글자로 보여 준다. 마지막으로 읽은 시각도 보여 준다. 읽기에 실패하면 이전 값을 지우지 않고 "통신 실패"를 표시한다.
- **명령 보내기:** 1.2절의 우편함 규칙대로 보낸다. D01001이 0이 된 것으로 PLC 처리를 확인하고, PLC 자리를 보고 거부를 확인한다.
  - **목요일 코드를 쓴다면 주의:** 목요일 코드는 쓰기 직후 같은 주소를 다시 읽어 요청값과 같은지 확인한다. 우편함 방식에서는 PLC가 0으로 지우므로 이 확인이 "불일치"로 나온다. **0은 "접수됨"으로 해석**하도록 바꾼다.
- **로그 창:** 보낸 명령, 처리 확인, 상태 코드 변화를 시각과 함께 남긴다. 파일로도 저장한다.
- **자동 운전:** 1.4절 순서를 PC 코드로 구현한다. 그동안에는 개별 버튼을 막는다.

## 7. 안전

- **UI의 "즉시 정지"는 비상정지가 아니다.** 통신과 스캔을 거치므로 늦게 도착하거나 아예 도착하지 않을 수 있다. 비상정지는 로봇의 하드웨어 E-stop을 쓴다.
- 첫 실행은 로봇 저속으로 한다. 비상정지 버튼을 손이 닿는 곳에 둔다.
- 같은 COM 포트를 QModMaster와 PC 프로그램이 동시에 열지 않는다.

## 8. 제출물

4. 6절 시험 표와 근거 로그 파일
